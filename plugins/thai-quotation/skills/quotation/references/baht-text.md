# baht-text — การแปลงจำนวนเงินเป็นข้อความ "บาทถ้วน" ภาษาไทย

เอกสารอ้างอิงสำหรับสคริปต์ `scripts/baht_text.py` ที่แปลงจำนวนเงิน (ตัวเลข)
ให้เป็นข้อความภาษาไทยตามมาตรฐานการอ่านจำนวนเงิน (อิงพฤติกรรม Excel `BAHTTEXT`)

> **กฎสำคัญ:** ช่อง `{{AMOUNT_IN_WORDS}}` ในใบเสนอราคา **ต้องได้จากการรันสคริปต์นี้เท่านั้น**
> ห้ามเขียน/คำนวณข้อความบาทถ้วนด้วยมือ (กันสะกดผิด/อ่านหลักผิด)

---

## วิธีเรียกใช้

```bash
python3 <path>/baht_text.py <amount>
```

- **ภาษา:** Python 3 — ใช้เฉพาะ standard library (ไม่มี dependency ภายนอก)
- **`<amount>`:** จำนวนเงิน เป็น int หรือทศนิยม (แนะนำ ≤2 ตำแหน่ง) เช่น `10700`, `1234.50`, `0.25`, `1000001`
- **เอาต์พุต:** พิมพ์ออก stdout **บรรทัดเดียว** = ข้อความบาทถ้วนภาษาไทย ไม่มีคำ/สัญลักษณ์อื่นต่อท้าย
- **exit code:** `0` เมื่อสำเร็จ; ถ้า input ผิดให้พิมพ์ error ไป **stderr** และ exit code ไม่เท่ากับ 0

ตัวอย่าง:

```bash
$ python3 baht_text.py 10700
หนึ่งหมื่นเจ็ดร้อยบาทถ้วน

$ python3 baht_text.py 1234.50
หนึ่งพันสองร้อยสามสิบสี่บาทห้าสิบสตางค์

$ python3 baht_text.py 0.25
ยี่สิบห้าสตางค์
```

การเรียกจาก skill (ดู `SKILL.md`) ใช้รูปแบบ:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/quotation/scripts/baht_text.py" <amount>
```

## กฎการอ่านจำนวนเงินภาษาไทย

| กฎ | รายละเอียด | ตัวอย่าง |
|----|-----------|---------|
| **หลักสิบ = "สิบ"** | เลข 1 ในหลักสิบ อ่านว่า "สิบ" ไม่ใช่ "หนึ่งสิบ" | `10` → สิบ |
| **เลข 2 หลักสิบ = "ยี่สิบ"** | เลข 2 ในหลักสิบ อ่านว่า "ยี่สิบ" ไม่ใช่ "สองสิบ" | `20` → ยี่สิบ |
| **หลักหน่วยเลข 1 = "เอ็ด"** | เลข 1 ในหลักหน่วย อ่านว่า "เอ็ด" **เมื่อมีหลักสูงกว่านำหน้า** (ไม่ใช่หลักซ้ายสุดของทั้งจำนวน) | `11` → สิบเอ็ด, `21` → ยี่สิบเอ็ด, `101` → หนึ่งร้อยเอ็ด |
| **เลข 1 โดด ๆ = "หนึ่ง"** | เลข 1 ที่เป็นหลักซ้ายสุด (ค่าตั้งต้น) อ่านว่า "หนึ่ง" | `1` → หนึ่ง, `1,000,000` → หนึ่งล้าน |
| **หลักล้าน (recursive)** | ทุก 6 หลักวนกลับมาใช้คำว่า "ล้าน" รองรับเลขใหญ่ ≥7 หลักและซ้อนได้ ("ล้านล้าน") | `21,000,000` → ยี่สิบเอ็ดล้าน, `10^12` → หนึ่งล้านล้าน |
| **ลงท้าย "ถ้วน"** | ถ้าไม่มีเศษสตางค์ (สตางค์ = 0) ลงท้ายด้วย "บาทถ้วน" | `1,000` → หนึ่งพันบาทถ้วน |
| **สตางค์** | ถ้ามีเศษสตางค์ อ่านส่วนสตางค์ด้วยกฎเดียวกับจำนวนเต็ม + "สตางค์" | `1234.50` → ...บาท**ห้าสิบสตางค์** |
| **0 บาทมีสตางค์** | ถ้าจำนวนบาท = 0 แต่มีสตางค์ → ขึ้นต้นด้วยสตางค์เลย ไม่มี "ศูนย์บาท" | `0.25` → ยี่สิบห้าสตางค์ |
| **ศูนย์** | `0` → ศูนย์บาทถ้วน | `0` → ศูนย์บาทถ้วน |

### กฎ "เอ็ด" เป็นกฎระดับทั้งจำนวน (ไม่ใช่ต่อกลุ่มล้าน)

นี่คือจุดที่ implementation แบบ recursive ต่อกลุ่มมักพลาด:

- `1,000,000` → กลุ่มล้านมีค่า `1` แต่อ่าน **"หนึ่ง"**ล้าน (เพราะ 1 คือหลักซ้ายสุด)
- `1,000,001` → หลักหน่วยมีค่า `1` อ่าน **"เอ็ด"** (เพราะมีหลักล้านนำหน้า) → **หนึ่งล้านเอ็ดบาทถ้วน**

เลข 1 ตัวเดียวกัน แต่ออกเสียงต่างกันตามตำแหน่ง สคริปต์จึงใช้วิธีอ่าน
**แบบ single-pass ไล่ทีละหลักจากซ้ายไปขวา** แล้วตัดสิน "เอ็ด" จากตำแหน่ง
ของหลัก (เป็น "เอ็ด" ก็ต่อเมื่อ index ของหลักนั้นไม่ใช่ 0 = ไม่ใช่หลักซ้ายสุด)

## หลักการทำงานของสคริปต์ (สรุป)

1. **parse** argument ด้วย `decimal.Decimal(str(...))` — ใช้ `Decimal` แทน `float`
   เพื่อกันค่าทศนิยมเพี้ยนจาก binary floating point (สำคัญสำหรับงานการเงิน)
2. **ปัดเศษ** เป็น 2 ตำแหน่งแบบ `ROUND_HALF_UP` (ปัดครึ่งขึ้น ตามมาตรฐาน Excel
   BAHTTEXT — ต่างจากค่า default ของ Python ที่เป็น banker's rounding)
3. **แยก** เป็นจำนวนเต็ม "บาท" และจำนวนเต็ม "สตางค์" (0–99)
4. **อ่าน** แต่ละส่วนด้วย reader ตัวเดียวกัน (single-pass, position-based)
5. **ประกอบ** ผลลัพธ์ตามเงื่อนไขบาท/สตางค์ (ดูตารางด้านล่าง)

| บาท | สตางค์ | รูปแบบผลลัพธ์ | ตัวอย่าง |
|-----|--------|--------------|---------|
| > 0 | = 0 | `<บาท>บาทถ้วน` | หนึ่งพันบาทถ้วน |
| > 0 | > 0 | `<บาท>บาท<สตางค์>สตางค์` | หนึ่งพัน...บาทห้าสิบสตางค์ |
| = 0 | > 0 | `<สตางค์>สตางค์` | ยี่สิบห้าสตางค์ |
| = 0 | = 0 | `ศูนย์บาทถ้วน` | ศูนย์บาทถ้วน |

## ข้อจำกัด และการจัดการ input พิเศษ

- **ช่วงตัวเลข:** รองรับเลขใหญ่ได้ไม่จำกัดด้วยหลัก "ล้าน" แบบวนซ้ำ (เช่น "ล้านล้าน")
  เพียงพอเกินพอสำหรับยอดเงินในใบเสนอราคา ในทางปฏิบัติแนะนำใช้กับยอดที่สมเหตุสมผล
- **การปัดเศษ:** ปัดทศนิยมเป็น 2 ตำแหน่งแบบ ROUND_HALF_UP ก่อนแปลงเสมอ
  เช่น `1.005` → ปัดเป็น `1.01` → "หนึ่งบาทหนึ่งสตางค์"; `1.004` → `1.00` → "หนึ่งบาทถ้วน"
  ทศนิยมเกิน 2 ตำแหน่งจะถูกปัด ไม่ถือว่าผิด (สอดคล้องกฎ "ปัดก่อนแปลง" ของ contract)
- **จำนวนติดลบ:** รับได้ โดยใส่คำว่า **"ลบ"** นำหน้า เช่น `-5` → "ลบห้าบาทถ้วน"
  (เลือกแนวทางนี้แทนการ reject เพื่อความยืดหยุ่น เผื่อกรณีปรับปรุง/เครดิตยอด;
  อย่างไรก็ตามยอดในใบเสนอราคาปกติเป็นค่าบวก)
- **input ผิดรูป:** ถ้าแปลงเป็นตัวเลขไม่ได้ (เช่น `abc`, ค่าว่าง) หรือเป็น
  `NaN`/`Infinity` → พิมพ์ข้อความ error ไป **stderr** และคืน exit code ไม่เท่ากับ 0
  - แปลงไม่ได้ / NaN / Infinity → exit code `1`
  - ไม่ได้ส่ง argument มา (จำนวน argument ไม่ถูกต้อง) → exit code `2`
- **ไม่มี side-effect:** สคริปต์อ่าน argument อย่างเดียว ไม่เขียนไฟล์/ไม่ต่อเน็ต
